# TaskNote：任务日期与时间体验设计

**状态：已完成并复核**

## 背景

新建待办时，日期选择器已经支持保存 `date` 与 `time`，但任务卡片只展示日期。列表排序优先级目前是任务旗标和创建时间，设置的截止日期/时间不会影响排序。用户因此难以从列表判断任务的实际先后顺序。

## 目标

让已经保存的任务日期和时间在待办列表中清晰可见，并让未完成任务按截止时间自然排序；不迁移或重写现有用户数据。

## 方案

- 继续使用现有 `date`、`time` 字段，不增加字段，也不改 Supabase schema。
- 任务行显示原有日期；有时间时，在日期旁显示时间。
- 未完成任务先按日期升序排列；同一天有时间的任务按时间升序排列，无时间的全天任务排在该日期有时间任务之后；缺少有效日期的任务排在有日期任务之后。
- 截止时间相同的任务再按旗标优先级排序，最后按创建时间从新到旧稳定排序。
- 已完成任务继续置于未完成任务之后，并沿用当前按创建时间从新到旧的顺序。
- 保留现有“已过期 / 待完成 / 已完成”分组与过滤逻辑。

## 不在本项范围

- 日期选择器中的“提醒”和“重复”入口仍单独规划；浏览器通知和重复任务涉及不同的数据与运行约束，后续分别评估、实现和复核。
- 不增加小时/日历视图、专注计时、任务 OKR 关联或其他列表重构。

## 验收标准

1. 有截止时间的待办在列表中同时显示日期和 `HH:mm` 时间；无时间待办仍只显示日期。
2. 未完成任务按日期、时间排序；高优先级只在截止时间相同的情况下作为次级排序。
3. 同一天的无时间待办排在该日期的定时待办之后；无有效日期待办位于所有有日期的未完成待办之后。
4. 过期、今天、未来的分组仍正确，已完成任务仍位于列表末尾。
5. 既有数据读取、保存、导出和同步格式不变；刷新页面后日期与时间仍保留。
6. 在本地预览中手动复核不同日期、同日不同时间、无时间、过期和已完成样例，并检查移动窄屏布局与浏览器控制台。

## 风险与处理

- 部分旧记录可能没有日期或时间：渲染时按缺省规则处理，不要求用户先迁移数据。
- 排序优先级会从“旗标优先”调整为“截止时间优先”：旗标仍保留，但只作为同一截止时间下的次级排序。
- 本项不触发通知，也不会在后台定时运行；提醒能力单独讨论和复核。
