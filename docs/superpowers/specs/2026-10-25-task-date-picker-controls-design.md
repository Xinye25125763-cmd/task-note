# TaskNote 日期控件、提醒与重复任务设计

**状态：已批准，实施中**

## 目标

修复待办日期弹层中时间、提醒和重复选项无法使用的问题。用户可以设置截止时分、提前提醒和重复规则；开启云同步并授权浏览器推送后，即使关闭 TaskNote 页面，也能收到尽力送达的系统通知。

## 当前原因

- 时间行只在空值和固定 `09:00` 之间切换，没有时分输入控件。
- “提醒”和“重复”是没有点击处理器的静态行。
- 待办数据目前只保存 `date` 与 `time`，没有提醒或重复规则。
- 项目没有通知权限申请、服务工作线程、推送订阅、服务端调度或重复任务生成逻辑。

## 方案

采用**浏览器 Web Push + Supabase 服务端定时发送**：

1. 日期弹层使用 24 小时制时分选择；提醒和重复行打开可操作的选择器。
2. 提醒规则随待办保存在现有 `user_data.data` JSON 中，并参与现有云同步、导入和导出。
3. 用户必须登录 TaskNote、开启云同步，并在具体设备/浏览器上主动开启系统通知。前端注册站点根目录 Service Worker，通过 Push API 订阅；订阅的创建、更新和注销都经由校验登录身份的 Supabase Edge Function。
4. 新数据库迁移建立私有 `push_subscriptions`、待发送 `task_reminders` 和发送记录表。`user_data` 更新触发器将有效、未完成且设置了提醒的任务整理到提醒索引表；浏览器客户端不能直接读取这些后台表。Edge Function 每分钟检查到期提醒并发送 Web Push，Service Worker 收到后展示系统通知。按任务提醒计划 ID、发送时刻和订阅端点记录投递结果，成功记录不会在正常重复扫描中重发；推送服务响应不确定时仍无法保证绝对 exactly-once。过期订阅会清理。
5. VAPID 私钥、函数调用凭证和 Supabase service role 凭证只放在 Supabase Vault/Edge Function secrets，不放在前端、Git 仓库或普通任务 JSON 中。VAPID 公钥可用于浏览器订阅。

Supabase 官方支持用 `pg_cron` 配合 `pg_net` 定时调用 Edge Function，并建议将定时调用凭证存入 Vault：[Supabase 定时调用 Edge Functions](https://supabase.com/docs/guides/functions/schedule-functions)。Web Push 通过 Service Worker 接收消息；Push API 与 Service Worker 需要安全上下文（HTTPS）：[MDN Push API](https://developer.mozilla.org/en-US/docs/Web/API/Push_API)、[MDN Service Worker API](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API)。

## 本次范围

- **时间**：选择 `HH:mm`；清除时间表示全天任务。提醒仅在同时存在有效截止日期和时间时可用。
- **提醒**：不提醒、到期时、提前 5/15/30 分钟、提前 1 小时。允许同一用户在多个浏览器/设备分别订阅。开启提醒时解释用途并由用户点击触发权限申请；拒绝权限、不支持 Push 或未登录/未云同步时，显示明确状态，不伪称后台提醒已启用。
- **重复**：不重复、每天、每周、每月。完成一项重复任务后保留已完成的本期，并生成下一期，保留时间、提醒和重复规则；每月对应日期不存在时取当月最后一天。若用户晚于原定日期才完成，则跳过已经过去的周期，生成完成时之后最近的一期，避免补出一串过期任务。撤销完成再完成不得在同一设备重复创建同一期。跨设备并发仍受现有整份 JSON 同步模型限制。
- **日期与时区**：待办保留本地日期/时间用于展示，并在启用提醒时保存 IANA 时区；数据库触发器据此计算 UTC 推送时刻，避免误按服务器时区发送。夏令时切换采用目标时区的本地墙上时间解释。
- **推送调度**：服务端调度每分钟扫描一次；提醒会有调度和推送网络延迟，目标是分钟级，不能保证精确到秒或在设备离线、系统禁用通知时送达。推送正文使用通用提示，不包含任务正文，降低锁屏泄露风险；点击通知打开 TaskNote。
- **设置持久化**：新待办字段随现有 JSON 云同步/导入/导出。推送订阅按登录用户与设备单独管理；在当前设备关闭后台提醒或退出账号时，注销该设备的订阅。
- **部署配置**：仓库提供数据库迁移、Edge Functions、Service Worker 和配置说明；发布前需要把迁移应用到 Supabase，启用 `pg_cron` / `pg_net`，配置 VAPID 与函数 secrets，部署函数并建立每分钟调度，再发布静态站点。任何秘密均通过 Supabase Dashboard/CLI 配置，不写进 Site 源码。

## 非目标

- 保证离线设备、浏览器/操作系统关闭通知或不支持 Web Push 的环境必达。
- 自定义重复间隔、指定多个星期日、结束日期或次数限制。
- 复杂的通知历史中心、短信/邮件提醒、跨设备实时冲突解决。
- 重构整个日期弹层或增加新日历视图。

## 验收

1. 用户能选择任意有效小时和分钟；重新打开时分控件仍显示已选值；全天任务不显示虚构时间。
2. 用户能保存、修改和清除提醒；只有登录、同步、订阅且权限可用的设备显示“后台提醒已开启”。
3. 到期提醒在页面关闭时能由受支持浏览器的系统通知收到；正常重复调度不会重复发送；已完成、删除或改期的任务不再发送旧提醒。推送确认状态不确定时允许极少数重复或遗漏，并向用户说明是尽力送达。
4. 用户能保存、修改和清除重复规则；完成后生成正确下一期，月份边界正确。
5. 设置在刷新、导出、导入和现有云同步后保留；退出/取消订阅后，该设备不再收到推送。
6. 数据库 RLS 阻止匿名用户和其他用户读取或写入订阅、提醒与发送记录；所有服务端凭证只存在 Supabase secret 存储中。
7. 日期、时间排序和过期/待办分组不退化；窄屏弹层、通知权限拒绝、未登录、浏览器不支持等状态均有可理解反馈。

## 风险与处理

- 浏览器或系统可延迟/抑制推送；只承诺尽力送达，并在设置界面说明当前订阅状态。
- 每台设备分别需要用户授权。iOS 等平台的 Web Push 行为可能因系统版本和安装方式而不同；能力检测失败时不显示已启用。
- 调度扫描间隔为一分钟且网络传输存在延迟；以“接近设定时刻”验收，不把它描述为精准闹钟。
- 服务器解析待办 JSON 时必须严格校验日期、时间、偏移量和时区，不能让坏数据中断整批任务扫描。
- 跨设备同时编辑仍受现有整份 JSON 同步模型约束；本项不改变同步架构。
